# 현황 동기화 가이드 (sync guide)

이 문서는 `data/status.json`을 **누가, 언제, 무엇을 고치는지** 정한 규칙입니다.
화면(`index.html`)은 이 파일만 읽으므로, 데이터 형식만 지키면 디자인을 건드릴 필요가 없습니다.

---

## 1. 기본 규칙

| 규칙 | 내용 |
|---|---|
| 단일 출처 | 화면에 보이는 모든 값은 `data/status.json`에서만 온다. `index.html`에 문구를 직접 쓰지 않는다 |
| 갱신 시각 | 값을 고칠 때마다 `updated_at`을 현재 KST 시각(`YYYY-MM-DDTHH:MM:SS+09:00`)으로 바꾼다 |
| 기록자 | `updated_by`에 고친 주체를 적는다(`초큐티`, `하람 비서` 대신 메인/협업 기기 기준 표기) |
| 사실만 | 확인된 것만 적는다. "예약 완료"와 "공개 완료"는 다르다 — 스튜디오에서 상태를 본 뒤에 바꾼다 |
| 하루 단위 | 날짜가 바뀌면 `youtube`의 `오늘` 블록을 지우고, 내일 블록을 오늘로 올린 뒤 새 내일 블록을 추가한다 |
| 개인정보 금지 | 아래 4장 참고. 저장소는 공개다 |

검사 → 커밋 → 푸시. 푸시 후 1분 안에 반영된다.

```bash
python3 scripts/validate_status.py && git add -A && git commit -m "status: …" && git push
```

## 2. 항목별 작성법

### `characters[]` — 오피스 맵의 세 캐릭터

```json
{
  "id": "chuchu",            // 고정값: chuchu | haram | keyring (그림이 id로 갈린다)
  "name": "초큐티",
  "mark": "ㅊ",              // 이름표 배지 글자
  "color": "#F7A8C0",        // 방 색 (SVG 벽·조명·가구 색이 여기서 파생)
  "deep": "#D2657F",         // 진한 강조색
  "device": "메인 기기",
  "role": "메인 비서 · 제작·발행 총괄",
  "state": "가동 중",         // "가동 중" | "대기"  (대기면 점이 노란색)
  "now": "지금 하는 일 한 줄 (25~45자 권장)",
  "duties": ["상시 담당 4개 정도"],
  "next": "다음 예정 한 줄"
}
```

- `now`는 **현재 시제 한 줄**. 길면 카드가 길어지므로 45자 안쪽을 권장한다.
- 담당이 바뀌면 `duties`를 고치고, 3곳이 겹치지 않는지 확인한다(같은 일을 두 곳이 하면 현황판이 거짓말이 된다).
- 일이 끝나 대기 상태면 `state`를 `대기`로.

### `youtube[]` — 18:00 예약 현황

```json
{
  "date": "2026-11-27",
  "label": "오늘 · 11/27 (금)",
  "time": "18:00",
  "state": "예약 완료",          // 그날 6편 전체의 상태
  "slots": [
    { "channel": "생존 D-DAY", "color": "#E0592F", "type": "롱폼",
      "title": "EP.08 — 재난 엿새째, 대피소가 열린다", "url": "https://youtu.be/…" }
  ]
}
```

- 채널 4곳 고정 색: 생존 `#E0592F`, 역전 `#7C5CFF`, SquishPop `#F2789F`, PopLoop `#2BB3A3`.
- 보통 하루 6편: 생존(롱폼+쇼츠) · 역전(롱폼+쇼츠) · SquishPop(쇼츠) · PopLoop(쇼츠).
  수·일요일에는 SquishPop·PopLoop 롱폼이 더해진다.
- `title`은 영상 제목을 그대로 쓰지 말고 **앞부분 30자 + 주제**로 줄인다(카드 폭 때문).
- `state`는 시간이 지나면 `예약 완료` → `공개 완료`로 바꾼다. 18:05 공개 확인 후.

### `publishing[]` — 블로그 · 클립 · 쓰레드

```json
{
  "platform": "블로그", "icon": "📝",
  "name": "라이프치트키", "account": "lifecheatlab",
  "owner": "메인 기기",           // 담당 기기
  "slot": "08:30",               // 예정 시각
  "title": "글 제목 (30자 이내)",
  "url": "https://blog.naver.com/…",   // 없으면 빈 문자열
  "status": "발행 완료",          // 발행 완료 | 예약 | 예정 | 진행 중
  "note": "한 줄 메모 — 이미지 장수, 개편 내용 등"
}
```

- 매일 도는 순서: 08:30 라이프치트키 → 09:05 클립(4890194) → 11:00 오늘의 생활혜택 → 14:30 쓰레드 → 17:40 클립(7728194).
- 새 글이 올라가면 그 줄의 `title`·`url`·`status`만 교체한다. 줄을 새로 추가하지 않는다(길어진다).

### `campaigns[]` — 체험단 · 크몽 · 공모전

`bars`(숫자 진행률) 또는 `lines`(문장 목록) 중 하나를 쓴다.

```json
{ "id": "experience", "icon": "🎁", "title": "체험단",
  "headline": "오늘 3곳 47건 신청 · 신규 당첨 0건",
  "bars": [ { "label": "무신사", "done": 28, "total": 125, "color": "#111111", "note": "남은 97건 19:00 회차" } ] }
```

- `done`/`total`은 **그날 회차 기준**. 누적 실적은 `headline`에 적는다.
- 크몽·공모전은 `lines`로: 심사 상태, 다음 확인일, 접수한 출품안 이름 정도만.

### `contests_upcoming[]` — 발표 일정

`{ "date": "12/03", "label": "화훼 공모전 발표" }` 형태. 지난 날짜는 삭제한다.

### `timeline[]` — 오늘의 타임라인

`{ "time": "18:00", "label": "유튜브 6편 공개", "owner": "예약", "done": false }`

- 끝난 항목은 `done: true`(취소선 표시). 자정이 지나면 다음 날 것으로 교체한다.

## 3. 반영 확인

1. `python3 scripts/validate_status.py` — 오류 0이면 통과, 요약 표를 보여 준다.
2. `git commit` / `git push`.
3. 라이브 주소를 열어 상단 시계 옆 "현황판 갱신 N분 전"이 방금으로 바뀌었는지 확인한다.
   (반영이 안 보이면 강력 새로고침 — `index.html`이 `?v=타임스탬프`로 캐시를 피한다.)

## 4. 공개 저장소 — 절대 넣지 않는 것

저장소 `dmstjr9706-crypto/Pickle-office`는 **누구나 볼 수 있다.** 다음은 코드·JSON·커밋 메시지·이슈 어디에도 넣지 않는다.

- 전화번호, 집 주소, 생년월일, 주민등록번호
- 계좌번호, 카드번호, 비밀번호, 인증번호, API 키, 토큰, 쿠키
- 이메일 주소 원문(계정을 가리킬 때는 `lifecheatlab`, `7728194` 같은 **공개 아이디**만)
- 로그인 화면 캡처, 세션 정보, 결제 정보
- 제3자의 실명·연락처 등 당사자가 공개를 원하지 않는 정보

`validate_status.py`가 전화번호·이메일·주민번호·계좌번호 패턴을 잡으면 **커밋을 멈추고** 해당 위치를 알려 준다.
검사에 걸리지 않더라도 사람이 한 번 더 읽고 올린다.

## 5. 손대지 말 것

- `characters[].id` 값(`chuchu`/`haram`/`keyring`) — 그림 분기 키다.
- `index.html`의 `render*` 함수가 읽는 키 이름 — 이름을 바꾸면 화면이 비어 버린다.
  항목을 늘리는 것은 배열에 원소를 추가하는 방식으로만 한다.
